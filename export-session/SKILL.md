# Export Session

Follow the target project's interaction and artifact languages from [language policy](../_agents/language-policy.md); pass both to delegates.

Export the current session as faithful Markdown and a raw archive. The main session identifies the tool/session/issue; an exporter performs format conversion.

## When to use

The user requests a session export, wants to archive before ending, or needs a record for review/sharing.

## Core disciplines

1. The main session resolves context and issue binding; the child only converts format.
2. Produce readable Markdown plus raw JSONL where available.
3. Preserve original messages and order without summary or rewriting; copy source JSONL unchanged.
4. Bind the filename to the parent product issue when several issues were discussed: Spec before ticket.
5. Explain degraded output when storage cannot be read.

## Workflow

### Step 1: Identify the tool

| Tool | Evidence |
|------|----------|
| Claude Code | `CLAUDE_CODE_SESSION_ID` or `~/.claude/projects/` |
| Codex | `CODEX_SESSION_ID` or `~/.codex/sessions/` |
| Pi | `~/.pi/agent/sessions/` |
| Cursor | `~/Library/Application Support/Cursor/User/globalStorage/state.vscdb` |

Ask the user if the tool is unclear.

### Step 2: Locate the session

**Claude Code:** `~/.claude/projects/<escaped-project-path>/<sessionId>.jsonl`. Escape `/Users/edy/tools/pi` as `-Users-edy-tools-pi`. Use the session environment variable if present; otherwise choose the latest modified JSONL candidate and confirm it.

**Codex:** `~/.codex/sessions/<year>/<month>/<day>/rollout-<timestamp>-<id>.jsonl`. Propose today's latest file and confirm it.

**Pi:** `~/.pi/agent/sessions/<project-directory>/<timestamp>_<id>.jsonl`, with directory names such as `--Users-edy-pro-zss-admin--`. Propose the matching project's latest file and confirm it.

**Cursor:** Read its SQLite store. `composerHeaders` values are JSON containing composerId, name, workspaceIdentifier.uri.fsPath for project matching, and lastUpdatedAt in milliseconds. `cursorDiskKV` keys are `bubbleId:<composerId>:<messageId>`; values hold type 1/user or 2/assistant, original text, and ISO createdAt.

Example lookup:

```sql
-- 1. 找当前项目的所有会话，按最后更新排序
SELECT json_extract(value, '$.composerId'),
       json_extract(value, '$.name')
FROM composerHeaders
WHERE json_extract(value, '$.workspaceIdentifier.uri.fsPath') = '<当前工作目录>'
ORDER BY json_extract(value, '$.lastUpdatedAt') DESC;

-- 2. 取最新会话，向用户确认（标题 + 时间）
```

For multiple sessions in the project, show the first five titles/update times and let the user choose. Do not silently select the newest Cursor session.

If queries are empty or fields differ after a Cursor update, explain that storage format may have changed and ask for Cursor's built-in Chat panel → Export Chat output. With that file, a later `/export-session` can produce **session.md only**; raw bubble metadata is unavailable, so it cannot reconstruct session.jsonl. Distinguish this fallback from the normal two-file export.

### Step 3: Resolve the issue

When a session spans several issues, bind to the parent product issue.

| Tracker/source | Reference | Filename identifier |
|----------------|-----------|---------------------|
| GitHub | `#123` or full issue URL | `123` |
| GitLab | `#123` or full issue URL | `123` |
| Linear | `PROJ-123` | `PROJ-123` before normalization |
| Local files | Spec or ticket under `.scratch/<feature>/` | Feature slug or feature-ticket identifier |
| No issue | Exploration/temporary work | `no-issue` |

Read `docs/agents/issue-tracker.md` when available to narrow inference; local mode uses the feature slug.

Infer, in order:
1. A Spec reference generated by `/to-spec`: e.g. issue URL ending `/100` → `100`, or `.scratch/blog-comments/spec.md` → `blog-comments`.
2. Ticket references generated by `/to-tickets`, resolving their parent/feature. If only a Plan issue appears, follow its `Spec:` back to the Spec rather than using the Plan as the product parent.
3. A branch name: `feat/PROJ-123-comment` → `PROJ-123`; `feat/blog-comments` → `blog-comments`.

Present the inferred binding for confirmation. Example:

```
我检测到本会话可能关联以下 issue：

- spec: blog-comments（推断自 .scratch/blog-comments/spec.md）
  - ticket: 01-comment-model
  - ticket: 02-nested-replies

建议绑定: blog-comments

确认？或输入其他 issue 标识（回车跳过 = no-issue）：
```

Use a confirmed/replacement identifier. If the user skips, use `no-issue`; if inference fails, ask and allow the same skip. Normalize to kebab-case, removing `#` and replacing spaces with hyphens (`PROJ-123` → `proj-123`).

### Step 4: Export

Read execution-mode. Missing/invalid configuration defaults to subagent with a configuration notice; respect explicit overrides. Apply the model under the [shared model rules](../_agents/workflow-contract.md#基础模型); inline keeps the main model.

In subagent mode pass the exporter the source tool (`claude-code`, `codex`, `pi`, `cursor`), source session path (or Cursor project cwd), confirmed issueid/no-issue, and output directory. It follows `_agents/exporter.prompt.md`, writes the two files to `sessions/<project>-<issueid>-<date>/`, and reports paths/counts. It never summarizes or rewrites the session.

In inline mode follow that same role prompt directly. Parsing, Cursor fallback, and Markdown output rules have one source; only the executor changes.

### Step 5: Check outputs

Verify the normal path produces both `session.md` and `session.jsonl`. Markdown metadata includes tool, session ID, issue, time range, export time, and message counts. Number messages chronologically, preserve user/assistant text, and fold reasoning/tool calls in `<details>`. The raw archive is the original record; for Cursor it includes composer metadata and raw bubble JSON. Report N user/M assistant counts and paths.

### Step 6: Save both files

Default directory: `./sessions/<project>-<issueid>-<date>/`.

```
sessions/pi-100-2026-08-26/
├── session.md      # 可读 Markdown（Step 5 格式）
└── session.jsonl   # 原始会话文件副本（一字不动）
```

Use `<project-name>-<issueid>-<YYYYMMDD>`, taking the project name from cwd and the confirmed/normalized Step 3 identifier. Examples retain their existing naming convention:
- GitHub: `pi-100-2026-08-26`
- Linear: `zss-admin-proj-123-2026-08-26`
- Local feature: `pi-blog-comments-2026-08-26`
- No issue: `pi-no-issue-2026-08-26`

Do not split the content by issue: one complete session stays in one Markdown file, bound to its parent issue. Create the output directory if needed; copy raw JSONL without modification. Report its binding and counts.

## Outputs and boundaries

Normal output is `session.md` plus `session.jsonl` under the named session directory; the Cursor fallback yields only Markdown. This is archival conversion, not summarization. A live session may contain records only up to the export moment; for completeness export it from a later session after it ends.

Sessions may contain secrets. Remind the user to review them, or use `<REDACTED>` for environment-variable values in generated presentation; preserve raw-archive fidelity as specified above. Cursor storage is an internal format whose bubbleId/composerHeaders/type fields may change; use the declared fallback on mismatch and confirm ambiguous session choices.
